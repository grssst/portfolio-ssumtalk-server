# 썸톡 (SumTalk) Server

> 썸톡(SumTalk) 모바일 애플리케이션의 백엔드 서버

실제 서비스로 운영한 소셜 모바일 애플리케이션의 백엔드 프로젝트입니다.

회원 관리, 사용자 정보, 채팅, 재화 및 결제 등 서비스의 핵심 비즈니스 로직을 담당하며, AWS 환경에서 실제 서비스 서버로 운영했습니다.

---

## 🛠️ 기술 스택

### Backend

| 기술                | 사용 목적            |
| ----------------- | ---------------- |
| Java 21           | 서버 개발            |
| Spring Boot 3.3.2 | REST API 서버      |
| Spring Security   | 인증 및 보안          |
| JPA / Hibernate   | ORM 및 데이터 접근     |
| Gradle            | 프로젝트 빌드 및 의존성 관리 |
| MySQL             | 주요 서비스 데이터 저장    |
| DynamoDB          | 채팅 데이터 저장        |

### Infrastructure

| 기술             | 사용 목적        |
| -------------- | ------------ |
| AWS EC2        | 애플리케이션 서버    |
| AWS RDS        | MySQL 데이터베이스 |
| AWS S3         | 이미지 및 파일 저장  |
| AWS CloudFront | 이미지 CDN      |
| AWS DynamoDB   | 채팅 데이터 저장    |
| AWS Lambda     | 서버리스 작업      |
| AWS SQS        | 비동기 작업 처리    |

---

## 🏗️ 서버 구조

```text
Mobile Client
     │
     │ HTTPS / REST API
     ▼
┌──────────────────────┐
│     Spring Boot      │
│                      │
│ Controller           │
│      ↓               │
│ Service              │
│      ↓               │
│ Repository           │
└──────────┬───────────┘
           │
     ┌─────┼──────────┐
     ▼     ▼          ▼
   MySQL  S3       DynamoDB
```

Spring Boot를 기반으로 Controller → Service → Repository 계층으로 구성하여 비즈니스 로직과 데이터 접근 로직을 분리했습니다.

---

## 🔐 인증 및 보안

Spring Security를 활용하여 사용자 인증 및 접근 제어를 구현했습니다.

* 사용자 인증
* 인증된 사용자 API 접근 제어
* 비밀번호 등 민감 정보 보호
* API 요청에 대한 권한 관리

---

## 👤 주요 기능

### 회원 관리

* 회원가입
* 로그인
* 사용자 정보 관리
* 프로필 관리
* 회원 탈퇴

### 사용자 기능

* 사용자 프로필 조회
* 사용자 탐색
* 사용자 간 상호작용
* 차단 및 신고 등의 사용자 관리 기능

### 💬 채팅

사용자 간 1:1 채팅 기능을 제공합니다.

채팅 데이터는 일반적인 서비스 데이터와 분리하여 **Amazon DynamoDB**를 사용했습니다.

```text
Client
  │
  ▼
Spring Boot
  │
  ▼
DynamoDB
  │
  └── Chat Room / Message
```

### 🍬 재화 시스템

서비스 내에서 사용하는 재화 시스템을 구현했습니다.

* 재화 보유량 관리
* 재화 지급 및 차감
* 서비스 기능 이용에 따른 재화 처리
* 구독 상품 관리

재화 변동과 관련된 비즈니스 로직을 서버에서 처리하여 클라이언트의 임의 조작을 방지하도록 구성했습니다.

### 💳 결제

앱 내 상품 구매 및 구독 기능을 서버와 연동하여 처리했습니다.

클라이언트에서 전달된 구매 정보를 서버에서 검증하고 사용자 계정의 상품 및 재화 상태에 반영하도록 구현했습니다.

---

## 🖼️ 이미지 처리

사용자가 업로드한 이미지 및 파일은 **Amazon S3**에 저장했습니다.

```text
Mobile Client
      │
      ▼
Spring Boot
      │
      ▼
    AWS S3
      │
      ▼
 CloudFront
      │
      ▼
Mobile Client
```

이미지 저장소와 애플리케이션 서버를 분리하고 CloudFront CDN을 사용하여 이미지 전달 성능을 개선했습니다.

---

## 🗄️ 데이터베이스

서비스의 일반적인 데이터는 **MySQL**을 사용하고, 채팅 데이터는 **DynamoDB**를 사용했습니다.

### MySQL

주요 서비스 데이터:

* 사용자
* 프로필
* 재화
* 상품
* 결제
* 서비스 이용 기록

### DynamoDB

* 채팅방
* 메시지
* 채팅 관련 데이터

데이터의 특성과 접근 패턴에 따라 서로 다른 데이터 저장소를 사용했습니다.

## ⚙️ 비즈니스 로직

서비스의 주요 비즈니스 로직은 서버에서 처리하도록 구성했습니다.

예를 들어 재화를 사용하는 기능의 경우:

```text
사용자 요청
    ↓
인증 및 권한 확인
    ↓
사용 가능 여부 검증
    ↓
재화 보유량 확인
    ↓
비즈니스 로직 수행
    ↓
재화 차감
    ↓
DB 저장
    ↓
결과 반환
```

클라이언트에서 단순히 결과를 전달받는 것이 아니라 서버에서 필요한 조건을 검증하여 서비스 데이터의 일관성을 유지했습니다.

## 🚨 예외 처리

실제 서비스 운영 과정에서 발생할 수 있는 다양한 예외 상황을 고려했습니다.

* 잘못된 요청
* 인증되지 않은 요청
* 존재하지 않는 사용자
* 권한이 없는 요청
* 재화 부족
* 중복 요청
* 데이터베이스 오류
* 외부 서비스 연동 오류

API의 정상적인 응답뿐만 아니라 예외 상황에 대한 처리도 서버에서 담당하도록 구성했습니다.
